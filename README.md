# hifi-repeater

악기 연습을 위한 웹 녹음 프로토타입. 이름은 임시입니다. Android 앱 개발은 환경 구축 이후로 보류하고, 현재는 HTTPS 웹 버전을 우선 검증합니다.

## 실행

Node.js 22.18 이상(또는 24 이상), npm, OpenSSL이 필요합니다.

```sh
npm install
npm run dev
```

[http://localhost:5173](http://localhost:5173)에서 마이크 권한을 허용하세요. `localhost`는 HTTP에서도 브라우저가 마이크 사용이 가능한 보안 컨텍스트로 취급합니다. 이 주소는 현재 Mac에서만 사용할 수 있습니다.

같은 Wi-Fi의 휴대폰에서 시험하려면 공인 인증서가 적용된 HTTPS 배포 주소를 사용합니다. 로컬 네트워크에서 시험해야 한다면 아래 `mkcert` 방식으로 Mac과 휴대폰에 개발 CA를 명시적으로 신뢰시킨 뒤 `npm run dev:https`를 사용합니다.

Mac의 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 사용하는 브라우저의 권한도 허용해야 합니다. 휴대폰에서는 Mac과 같은 네트워크에 연결하고 Mac 방화벽의 개발 서버 연결을 허용해야 합니다.

### 로컬 HTTPS 실험 (선택)

`mkcert`가 설치되어 있고 사용자가 먼저 `mkcert -install`을 실행했다면 `npm run dev:https`는 mkcert 인증서를 사용합니다. 그렇지 않으면 자체 서명 인증서를 사용하며 신뢰되지 않습니다. 프로젝트 스크립트는 시스템 신뢰 저장소를 변경하지 않습니다.

브라우저 저장소는 주소별로 분리되므로 HTTP localhost와 HTTPS 주소에서 녹음 목록이 다른 것은 정상입니다.

## 검증

```sh
npm test
npm run test:e2e
npm run build
```

브라우저 테스트는 설치된 Google Chrome과 가상 마이크를 사용합니다. 테스트 환경에서만 자체 서명 인증서 오류를 허용합니다. 실제 마이크 음질과 휴대폰 지연은 실기기로 추가 검증해야 합니다.

## 현재 기능

- 독립된 연습 슬롯 3개와 슬롯별 테이크 이력
- 녹음 버튼을 다시 누르면 정지 후 자동 재생
- PCM 원본, 파형, 드래그/슬라이더 구간 지정, 선택 구간 확대, 구간 반복
- 이전 테이크 선택 비교, 별도 보관 표시, WAV 내보내기
- IndexedDB에 작업 자동 저장 및 다시 열 때 테이크와 구간 복구
- 설정 화면에서 앱 로컬 녹음·설정의 저장량 확인 및 삭제
- 선택적으로 녹음 재생에 iPhone → KM184 FIR 또는 IIR 기준 적용
- 앞 무음을 감지해 원본은 보존하고 재생 시작점만 조정
- 기기 외관 설정에 맞춘 밝은/어두운 화면

입력 에코 제거, 잡음 억제, 자동 게인 해제를 요청하지만 실제 지원은 장치마다 다릅니다. 저장 완료를 기다리지 않고 재생합니다. 모든 테이크는 현재 자동 삭제하지 않습니다. '보관'은 추후 정리 기능에서도 보존할 표시입니다. 설정에서 앱 로컬 데이터를 삭제할 수 있습니다. 브라우저 저장 데이터를 지우면 작업은 사라지므로 중요한 연주는 WAV로 내보내세요.

설정의 iPhone → KM184 FIR과 IIR은 한 동시 녹음 쌍으로 만든 실험 기준입니다. FIR은 train-only 4,097-tap 필터이며 입력 극성·레벨 보정이 들어 있습니다. IIR은 같은 분석에서 가져온 여섯 개의 넓은 최소 위상 피킹 필터를 직렬로 적용합니다. 다른 휴대전화나 녹음 설정에서의 변환 품질은 보장하지 않습니다. 필터는 재생에만 적용되고 원본 테이크와 WAV 내보내기는 바꾸지 않습니다. 설정 화면은 마지막 녹음 트랙에 대해 브라우저가 보고한 에코 제거·잡음 억제·자동 게인 설정도 보여줍니다.

## 프로토타입 범위

녹음 PCM은 메모리에 모이므로 짧은 프레이즈 연습이 현재 대상입니다. 녹음 중 새로고침하면 진행 중인 녹음은 복구되지 않습니다. 화면 잠금/백그라운드 녹음, 장기 녹음 스트리밍 저장, 입력 장치 선택은 후속 구현입니다.

`android/`와 `capacitor.config.ts`에는 생성해 둔 초기 스캐폴드만 남겨 두었습니다. APK 빌드·실기기 검증·네이티브 오디오·Android 파일 내보내기는 구현 완료 상태가 아니며, 웹 실행에는 Android SDK나 Java가 필요하지 않습니다.

## Nonlinear Microphone Conversion Model — 녹음 특성 변환 실험

휴대폰과 레퍼런스 마이크로 동시에 녹음한 음원 쌍을 이용해, 휴대폰 파형을
레퍼런스 녹음에 가깝게 변환하는 NAM A2 기반 실험입니다. 현재는 iPhone → KM184를 대상으로
Apple Silicon GPU(MPS)에서 Lite·Full을 학습하고 FIR 필터와 비교했습니다.
웹 녹음 앱에 통합된 기능은 아니며 `experiments/mic-modeling/`에서 독립적으로 실행합니다.

**이름은 `Nonlinear Microphone Conversion Model`을 사용합니다.** 일반적인 IR(impulse response)
컨볼루션은 선형 시불변 시스템을 표현하므로, `nonlinear IR-conversion`이라고 하면 IR 파일 자체를
변환하는 모델로도 읽힐 수 있습니다. 여기서 학습하는 것은 IR 파일이 아니라 두 녹음 사이의
시간 문맥을 가진 비선형 파형 변환입니다. FIR은 선형 비교 기준이며 NAM이 학습한 차이가
모두 마이크의 물리적인 비선형 특성이라는 뜻은 아닙니다.

| 항목 | 내용 |
|---|---|
| 입력 데이터 | 같은 연주를 동시에 녹음한 48 kHz WAV 쌍: 휴대폰 입력 / 레퍼런스 정답 |
| 전처리 | 시작 지연·극성·클록 드리프트 추정, 분수 샘플 정렬, fitting 구간 기반 레벨 보정 |
| 모델 | 공식 NAM A2의 3채널 Lite / 8채널 Full WaveNet을 각각 학습 |
| 학습 방법 | 파형 MSE + MR-STFT loss, 검증 ESR로 checkpoint 선택 |
| 데이터 분할 | 이번 76초 녹음의 0–50초 학습, 51–60초 검증, 마지막 15초 중 공통 구간 테스트 |
| 결과물 | `.nam`, PyTorch checkpoint, 전처리 계수, 변환 WAV, 비교 페이지 |

[학습 가이드 및 실험 결과](experiments/mic-modeling/README.md)에 **레퍼런스, 코드 구성,
환경 설치, 데이터 입력·교체 방법, 학습·평가·변환 실행 명령**을 정리했습니다.
현재 결과는 같은 녹음의 홀드아웃 평가이며, 다른 연주와 배치에서의 일반화는 미검증입니다.
