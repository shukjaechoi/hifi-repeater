## Q01 — 연주 시작점 자동 탐지

에너지/RMS, 적응형 노이즈 바닥, 지속 시간, 히스테리시스를 기준으로 유효 연주 시작점을 탐지한다. 필요하면 악기 대역 에너지와 spectral flux를 결합한다. 음성 VAD를 그대로 쓰지 않는다.

탐지점보다 조금 앞에서 재생하여 여린 어택을 보존한다. 원본을 자르지 않고 재생 오프셋만 저장한다. 수동 재조정·기능 해제를 제공한다. 여린 시작, 강한 어택, 주변 소음, 터치 소음, 잔향으로 평가한다. 탐지 실패 시 원래 시작점으로 재생한다.

## Q02 — xcorr 정렬

같은 연주 구간의 비교 시작점을 대략 맞춘다. 별도 연주끼리는 원시 파형 위상이 달라질 수 있어, 다운샘플한 에너지·온셋 엔벌로프의 정규화 상호상관을 우선 비교한다. 탐색 범위를 제한하고 신뢰도가 낮으면 자동 이동하지 않는다. 사용자가 오프셋을 조정할 수 있다.

이 기능은 일정 시간 이동만 추정한다. 연주 중 템포 변화는 해결하지 않는다. DTW·시간 늘이기는 별도 후순위이며 MVP에 포함하지 않는다. 오디오 보정용 동일 신호의 정밀 지연·클록 드리프트 정렬과 구분한다.

## Q03 — 화음 호출

후속 UI에 화음 호출 활성화 버튼과 등록 흐름을 추가한다. 대기 중 호출 화음 → 녹음 시작, 녹음 중 호출 화음 → 정지·자동 재생. 기본은 꺼짐, 사용자 활성화 시에만 마이크를 대기 상태에서도 사용한다.

기본 탐지 후보는 크로마/피치 클래스 패턴 + 최소 지속 시간 + 쿨다운이다. 실제 연주에 같은 화음이 등장하는 오탐을 평가하고, 필요하면 화음 두 번 또는 화음 순서를 호출 패턴으로 쓴다. 검출 지연과 호출 화음이 녹음 끝에 들어가는 문제를 함께 해결한다. 원본은 유지하고 재생 범위에서 호출 부분을 제외하는 안을 우선 검토한다.

스피커 재생을 호출 화음으로 오인하지 않도록 초기 후속 버전에서는 재생 중 탐지를 비활성화한다. 재생 중 호출까지 지원하는 것은 별도 실험으로 둔다. MVP에는 작동하지 않는 버튼을 노출하지 않는다.

## Q04 — 마이크 레퍼런스 매칭

목표: 특정 조건에서 휴대폰 녹음의 기타 음역대 음색을 KM184 등 선택한 레퍼런스 녹음에 가깝게 만든다. 레퍼런스의 절대적 평탄성 또는 연주자의 귀에서 들린 소리 재현을 목표로 간주하지 않는다.

1. 같은 연주를 휴대폰과 레퍼런스로 동시에 녹음한다. 서로 다른 테이크를 필터 추정의 정답 쌍으로 쓰지 않는다.
2. 두 마이크를 가능한 가까이 두고 위치·방향·거리·케이스·입력 경로·게인 조건을 기록한다. 두 센서가 같은 공간점에 있지 않으므로 악기 방사와 공간 차이가 남는다는 점을 평가한다.
3. 지연, 레벨과 서로 다른 녹음 클록의 드리프트를 정렬한다. 여러 음역·셈여림·주법을 포함한다.
4. 단순 스펙트럼 나눗셈 대신 정규화된 전달함수 추정 또는 최소제곱 필터를 사용한다. 대역 제한, 평활화, 최대 증폭량을 적용한다.
5. 완만한 EQ 또는 짧은 FIR을 첫 기준으로 사용한다. 필요한 필터 길이는 측정 결과로 결정하며 미리 성능을 보장하지 않는다.
6. 학습에 쓰지 않은 프레이즈·거리·셈여림에서 음량을 맞춘 청취 비교와 대역별 오차·클리핑·잡음 증가를 확인한다.

추론 연산보다 대표성 있는 측정 데이터와 조건 일반화가 핵심 리스크다. 무처리 입력이 불가능하거나 처리 특성이 시간·레벨에 따라 바뀌면 고정 필터의 적용 범위를 제한한다. 레퍼런스 데이터가 없으면 도구 준비는 가능하지만 유효한 프로필 생성은 미룬다.

## Q05 — 마이크 보정 통합

원본 → 마이크 프로필 → 재생 경로로 비파괴 적용한다. 원본/보정 A/B, 음량 맞춤, 프로필 우회, 적용 기기·입력 경로·측정 조건·버전을 저장한다. 원본 또는 마이크 보정본을 선택해서 내보낸다.

## Q06 — 스피커 재생 보정

알려진 신호 또는 레퍼런스 녹음을 휴대폰으로 재생하고, 정의한 청취 위치에서 레퍼런스 마이크로 측정한다. 재생 방향·거리·음량·OS 음향 효과를 고정하고 주변 위치도 평가한다.

마이크 측정의 목표 감도/응답을 고려하여 휴대폰 출력 경로의 전달함수를 추정하고, 정규화된 역 EQ를 계산한다. 과도한 저역 부스트와 깊은 상쇄점 보정은 제한한다. 여러 재생 음량에서 확인하고, 기기 내장 보호/리미터 때문에 레벨별 응답이 달라지는지 확인한다.

재생 체인: 원본 → 선택적 마이크 보정 → 출력 장치별 EQ → 헤드룸 관리/필요시 리미터 → 스피커. 리미터 동작이 연습 다이내믹 평가에 미치는 영향도 표시·검증한다. 이어폰/외부 출력으로 전환하면 휴대폰 스피커 프로필을 해제한다. 스피커 보정은 내보내기 파일에 포함하지 않는다.

## Q07 — NAM A2 비선형 모델

참고 저장소:

- 공식 학습 및 .nam 내보내기: https://github.com/sdatkinson/neural-amp-modeler
- CPU 기반 A2 학습 실험: https://github.com/mikeoliphant/nam-cpu-trainer
- 공식 문서: https://neural-amp-modeler.readthedocs.io

공식 저장소는 모델 학습과 .nam 내보내기를 담당하며 실시간 재생은 별도 파트너 프로젝트로 안내한다. 따라서 학습 파이프라인과 웹/Android 추론 엔진 통합을 별도 작업으로 평가한다. 앱 통합 전에 선택한 모델의 런타임 지원과 연산 비용을 확인한다.

2026-09-29 README 확인: 입력/출력 WAV로 NAM A2 모델 학습 가능. 기본 v3 NAM/Tone3000 신호를 기준으로 학습·검증 구간을 설정하며 다른 신호는 구간 설정이 맞지 않을 수 있다. 자동 입력/출력 정렬은 제공하지 않으며 프로젝트는 실험 단계로 설명되어 있다.

입출력 쌍을 이용한 학습이라는 발상은 적용 가능하지만, 경로 재현과 경로 보정은 구분한다. 스피커 입력→측정 출력을 학습하면 스피커 특성을 재현하는 순방향 모델이 된다. 이를 입력에 바로 적용해도 보정이 되지 않는다. 역필터/역모델 또는 순방향 모델을 이용한 보정기 최적화가 추가로 필요하다. 손실·포화된 정보는 일반적으로 완전 역복원이 불가능하다.

마이크에서는 휴대폰 녹음→레퍼런스 녹음으로 매핑을 학습하는 실험을 고려할 수 있다. 먼저 선형 EQ/FIR 대비 미사용 데이터 성능, 어택·셈여림 보존, 모바일 CPU·배터리 비용을 확인하고 실제 이득이 있을 때만 도입한다.

### 2026-09-29 추가 합의: 동시 녹음 기반 소형 신경망

사용자의 계획은 휴대폰과 KM184로 동시에 녹음한 쌍을 확보하고, 휴대폰 녹음 → KM184 녹음의 직접 변환을 학습하는 것이다. 이 방향을 Q07의 마이크 모델 실험 목표로 확정한다. NAM 기술문서 및 관련 연구를 검토한 뒤 작은 신경망을 직접 설계하는 것도 후보로 둔다. 현재 모델 구조를 확정하거나 효과를 단정하지 않는다.

동일 연주의 정렬된 데이터에서 선형 EQ/FIR과 소형 비선형 모델을 비교한다. 레퍼런스 위치 차이, 녹음 드리프트, 레벨과 AGC 상태를 통제한다. 학습 데이터와 다른 프레이즈·셈여림·거리에서 검증하여 단순한 음색 개선뿐 아니라 어택과 실제 연주 차이가 보존되는지 확인한다. 대상 음역 밖은 급격한 차단보다 완만한 대역 제한과 전이 대역을 사용하며, 기타 배음까지 무조건 제거하지 않도록 상한을 측정으로 정한다.

## Q08 — Android 개발 환경 및 네이티브 앱 (사용자 요청으로 보류)

우선 HTTPS 웹 버전을 실제 기기에서 검증한다. 이후 Java/Android SDK 및 실기기 환경을 구축하고 기존 스캐폴드부터 재개한다. 네이티브 입력 경로, 무처리 녹음, 파일 내보내기, 백그라운드 동작을 별도로 구현·검증한다. 현재 생성된 Android 프로젝트는 배포 가능한 앱으로 간주하지 않는다.
