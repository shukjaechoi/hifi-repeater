# hifi-repeater 개발 계획

수정일: 2026-09-29. 상태: HTTPS 웹 프로토타입 구현, 실기기 검증 예정. Android 앱은 보류.

## 제품 목표와 확정 사항

악기 연주 → 정지와 동시에 자동 재생 → 구간 반복 → 다시 연주의 흐름을 최소 조작으로 제공한다. 웹과 Android를 지원한다. 멀티트랙 믹싱·오버더빙은 범위에서 제외하고, 혼자 중주하기는 별도 앱 아이디어로 남긴다.

- 기본 작업구역은 3개다. 트랙은 동시 재생 채널이 아니라 독립된 연습 슬롯이다.
- 슬롯 용도는 자유롭다: 연습 시작/연습 중/마지막 확인 또는 서로 다른 프레이즈 A/B/C.
- 초기 표시는 슬롯 1/2/3으로 하고, 이름 변경은 선택 사항이다.
- 녹음 버튼을 다시 누르면 종료 후 자동 재생한다. 저장 대화상자는 없다.
- 파일명과 폴더 선택 없이 앱 내부 저장소를 사용한다. 명시적인 보관 및 파일 내보내기는 별도 동작이다.
- 원본 오디오는 유지하고 구간, 재생 시작점, 보정은 메타데이터 및 비파괴 처리로 관리한다.

## MVP

1. 슬롯 3개 전환, 슬롯별 현재 테이크·파형·반복 구간 유지.
2. 한 번 눌러 녹음, 다시 눌러 정지 및 자동 재생. 재생 중 녹음 버튼을 누르면 재생을 멈추고 새 테이크 녹음.
3. 재생 정지/다시 듣기 조작은 녹음 버튼과 구분한다. 재생 종료 후에는 대기 상태로 돌아간다.
4. 파형 표시, 탐색·확대, A–B 구간 선택 및 반복. 기본 자동 재생은 처음부터, 사용자가 지정한 구간이 있으면 해당 구간부터 재생.
5. 슬롯 간 또는 최근 테이크 간 순차 비교. 처음에는 각 테이크의 시작점·구간을 수동으로 지정한다.
6. 앱 내부 작업 상태 자동 복구, 선택한 테이크의 명시적 보관, WAV 내보내기.
7. 입력 레벨·클리핑 표시, 권한 거절·입력 중단·저장 실패 처리.

### 저장 정책 제안 — 구현 시 확정

- 작업 저장: 저장 버튼 없이 내부에 기록하며 정상적인 앱 재실행에서 복구한다. 영구 보관함과 구분한다.
- 슬롯 재녹음: 새 테이크를 만들고 직전 테이크를 되돌릴 수 있도록 보존한다. 녹음 성공 전에 이전 테이크를 삭제하지 않는다.
- 보관: 사용자가 선택한 테이크를 자동 정리 대상에서 제외한다.
- 내보내기: 사용자가 원할 때 파일로 저장한다. 기본 파일명은 자동 생성한다.
- 초기에는 자동으로 오래된 녹음을 삭제하지 않는다. 저장 한도와 최근 이력 수, 정리 규칙은 실사용 후 결정한다. 용량 부족은 녹음 전에 알린다.
- 웹 내부 저장소는 localStorage에 오디오를 넣지 않고 IndexedDB/OPFS 등으로 구현한다. 브라우저 데이터 삭제까지 영구 보존을 보장하지 않는다.

### 상태 전환 규칙

- 대기 → 녹음 → 정지 처리 → 자동 재생 → 대기.
- 반복 모드에서는 지정 구간을 반복하며 명시적으로 정지할 수 있다.
- 녹음 중 슬롯 변경은 초기 버전에서 비활성화한다. 재생 중 슬롯 변경은 기존 재생을 정지한다.
- 녹음 실패 시 기존 테이크를 유지한다. 빈 녹음을 자동 재생하지 않는다.
- 같은 버튼의 중복 입력과 정지 처리 중 재입력을 제어한다.

## 기술 방향 — 검증 후 확정

- 공통 UI와 세션 로직: React + TypeScript 후보.
- 웹: Web Audio/AudioWorklet 기반 PCM 경로 및 로컬 저장.
- Android: Capacitor 공통 UI + 네이티브 AudioRecord/AudioTrack 오디오 모듈 후보.
- 공통 오디오 인터페이스로 녹음, 재생, 탐색, 반복, 레벨, 파형 요약, 장치 정보, 후속 DSP를 분리한다.
- PCM 스트리밍과 재생 타이밍은 각 오디오 엔진이 담당하고 UI 브리지로 샘플 전체를 지속 전달하지 않는다.
- 초기에는 모노 녹음, 서버·로그인·동기화 없이 시작한다. 실제 샘플레이트와 입력 설정을 기록한다.
- 마이크 자동 게인·노이즈 억제·에코 제거 해제를 요청하고 적용 가능한 설정을 확인한다. 무처리 입력 지원 여부를 기기별로 검증한다.
- 후속 처리를 위한 데이터: 세션, 슬롯, 테이크, 원본 위치, 샘플레이트, 입력 경로, 반복 구간, 비교 오프셋, 프로필 버전.

## 구현 순서 및 검증 기준

### 0. 오디오 기술 검증

대상 휴대폰/브라우저에서 녹음→자동 재생, 파일 저장과 재생 준비 병행, 파형, 반복 재생을 검증한다. 전환 지연은 정지 입력부터 첫 유효 재생 샘플까지 측정한다. 유선·내장 스피커를 먼저 검증하고 Bluetooth 지연은 별도로 기록한다.

### 1. 연습 MVP

슬롯 3개, 녹음·자동 재생, 파형·반복, 수동 비교, 작업 복구·보관·내보내기를 완성한다. 슬롯별 녹음과 구간이 섞이지 않고, 재녹음 실패 시 이전 녹음이 남으며, 재실행 시 작업이 복구되어야 한다. 지원 플랫폼에서 권한/장치 중단과 장시간 녹음의 저장 동작을 확인한다.

### 2. 편의 기능

BACKLOG.md의 Q01–Q03을 순서대로 검증한다. 마이크 보정 데이터 수집은 이 단계와 독립적으로 준비할 수 있다.

### 3. 음향 보정 연구 및 통합

오프라인 마이크 EQ/FIR 실험 → 학습에 쓰지 않은 녹음으로 평가 → 앱에서 프로필 적용 → 스피커 보정 → 필요할 경우 비선형 모델 순서로 진행한다. 기기와 측정 데이터가 없으면 효과를 입증한 것으로 간주하지 않는다.

## 2026-09-29 구현 현황 및 우선순위 변경

사용자 요청으로 Android 환경 구축과 앱 개발은 보류한다. 웹 HTTPS 개발 및 검증을 우선한다. Android 스캐폴드는 보존하되 네이티브 오디오·패키징 완료로 간주하지 않는다.

웹 프로토타입 구현: 슬롯 3개, PCM 녹음, 정지 후 자동 재생, 파형 구간 선택·확대·반복, 이전 테이크 선택 비교, 작업 저장과 복구, 보관 표시, WAV 내보내기. 개발 서버는 로컬 HTTPS를 기본으로 사용한다. 원격 origin은 https://github.com/shukjaechoi/hifi-repeater.git 으로 설정했다.

남은 검증: 실제 Mac/휴대폰 마이크 권한과 음질·전환 지연, 전화/화면 잠금 중단. 남은 기능: 장기 녹음 스트리밍 저장 및 저장 용량 사전 확인, 입력 장치 선택, 녹음 정리 정책. Q01–Q07은 후속 큐 상태를 유지한다.
