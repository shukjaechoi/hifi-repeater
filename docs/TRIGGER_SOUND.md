# Trigger sound 기술 조사 및 설계안

조사일: 2026-10-01. 아래 설계안을 바탕으로 첫 실험 버전을 구현했다. 실기기 정확도는 아직 검증하지 않았다.

## 현재 구현 (2026-10-01)

- 설정에서 음악 패턴 등록/재등록/삭제 및 활성화. 특징 템플릿은 로컬에 저장하고 활성화는 세션마다 사용자가 선택한다.
- 외부 음성 모델이나 Meyda 의존성 없이 Worker에서 Goertzel 음정 스펙트럼(48음), chroma, 상대 에너지를 계산하고 제한된 DTW로 비교한다. 약 64 ms 프레임과 32 ms hop을 사용한다.
- 활성화 시 하나의 마이크와 AudioWorklet을 유지한다. 테이크 수집만 start/stop하며 대기 PCM은 저장하지 않는다. 분석 큐와 패턴 길이를 제한한다.
- 패턴 앞뒤 약 0.23초의 쉼이 필요한 구간 기반 실험이다. 0.2~4초 패턴이 대상이며 등록은 4.5초에 자동 종료한다. 긴 잔향이나 끊김 없는 연주에 섞인 패턴은 놓칠 수 있다.
- 재생/설정/상태 전환 중 제어용 감지를 중지한다. 재무장에 쉼을 요구하고 중복 검출을 차단한다. 등록 중 페이지 이동을 막으며 취소/권한 오류/오디오 중단을 처리한다.
- 정지 호출 길이를 사용해 재생 끝을 조정하며 원본은 유지한다. 구간 기반 경계 추정이므로 정확한 절단은 보장하지 않으며 B 슬라이더로 조정할 수 있다.
- 다중 샘플 등록, 등록 소리 미리 듣기, 별도 감지 시험 UI, 연속 입력 subsequence 탐지 및 네이티브 백그라운드 감지는 후속 작업이다.
- 합성 음으로 음량·속도·샘플레이트 변화 및 다른 음/역순 거부 단위 테스트, 실제 AudioWorklet/Worker를 사용하는 브라우저 등록→시작→정지·재생·마이크 유지/해제 테스트를 추가했다. 실제 악기·거리·방 소음의 검출률은 별도 실측이 필요하다.

이하 내용은 초기 조사 및 후속 설계 후보를 포함한다.

## 요구와 권장 출발점

사용자가 짧은 소리를 직접 녹음해 등록하고, 같은 소리를 다시 내면 대기 중에는 선택 슬롯 녹음을 시작하고 녹음 중에는 정지 후 자동 재생한다. 설정의 한 섹션에 등록 녹음과 활성화 체크박스를 둔다. 기존 Q03 화음 호출을 일반화한다.

첫 실험은 Meyda 특징 추출 + 시간축 템플릿 매칭(DTW)을 권장한다. Meyda는 MFCC, chroma, RMS 등의 추출 라이브러리이며 완성된 트리거 검출기가 아니다. 소리 구간 탐지, 정규화, DTW, 임계값 보정과 상태 제어는 앱에서 구현해야 한다. 한 번 등록하는 UX는 가능하지만 한 샘플만으로 거리·속도·주변 소음 변화에 강한 인식을 보장할 수 없다. 같은 소리를 3회 등록하는 옵션과 별도의 감지 시험을 권장한다.

## 기술 후보

| 후보 | 제공 기능 | 이 앱에서의 판단 |
| --- | --- | --- |
| Meyda + DTW | 브라우저에서 MFCC/chroma/RMS 추출, 별도 DTW로 특징 시퀀스 비교 | 별도 모델 학습 없이 등록한 소리를 비교하는 첫 실험에 적합. 정확도는 실측 필요 |
| TensorFlow.js speech-commands 전이학습 | 브라우저에서 예시 수집, 추가 학습, 추론 | 배경 소음과 트리거 예시를 여러 개 수집할 수 있다면 후속 후보. 단일 녹음 등록 UX에는 준비 과정이 더 큼 |
| Porcupine Web | WebAssembly 기반 wake word 인식, 사용자 지정 키워드 모델 | 말로 된 호출어가 목표일 때 후보. 임의의 화음·두드림 녹음을 그대로 등록하는 용도와는 다름. AccessKey와 서비스 조건 확인 필요 |
| openWakeWord | 학습된 wake word 모델 및 사용자 지정 모델 학습 도구 | 별도 학습·웹 통합 작업이 필요해 이번의 간단한 등록 흐름에서는 후순위 |

이 판단은 공식 문서와 현재 앱 구조를 비교한 설계 판단이며 성능 벤치마크 결과가 아니다.

## 입력과 비교

하나의 마이크 스트림을 공유한다. 원본 샘플은 기존 품질로 테이크에 기록하고, 감지용 복사본만 리샘플링·정규화한다. 등록 시와 감지 시 샘플레이트, 프레임 길이, hop, window 및 특징 정규화 설정을 동일하게 유지하고 버전을 함께 저장한다.

AudioWorklet은 PCM 수집과 샘플 위치 추적을 담당하고, 특징 추출·매칭은 Worker에서 처리하는 구조를 우선 검토한다. 대기 중에는 최근 몇 초의 제한된 버퍼만 유지하고 누적 녹음하거나 저장하지 않는다. 처리 지연이 생기면 오래된 감지 작업을 버려 메모리와 지연의 무한 증가를 막는다.

- 배경 에너지와 비교해 유효 소리 구간을 찾는다. 악기·타격음을 지원하므로 음성 VAD만으로 입력을 차단하지 않는다.
- MFCC로 음색의 시간 변화를 비교하고, 화음은 chroma, 두드림 패턴은 에너지/온셋 변화를 함께 평가한다. chroma만 쓰면 옥타브·음색 구별이 약해질 수 있다.
- 정규화된 특징 시퀀스를 제한된 속도 변화와 길이 범위 안에서 비교한다. 전체 입력을 평균한 특징 하나로 비교하지 않는다.
- 소리 구간 경계 기반 비교와 연속 입력 내 subsequence DTW를 비교 평가한다. 경계 방식은 가볍지만 연주·잔향과 겹친 정지 신호를 놓칠 수 있다.
- 최소 지속 시간, 유사도 임계값, 재감지 금지 시간, 소리 종료 후 재무장 조건을 조합해 한 번 낸 소리가 시작·정지를 연속 실행하지 않게 한다.
- 등록 샘플의 무음·클리핑·과도한 길이를 검증하고, 감지 시험에서는 녹음 상태를 전환하지 않고 일치 여부만 표시한다.

DTW는 길이/속도 차이를 일부 허용하는 수단이며, 소음·다른 소리와의 혼합·마이크 변화에 자동으로 강해지는 것은 아니다. 연주에 자주 등장하는 단일 화음보다 구별되는 짧은 패턴이 유리할 것으로 예상하며 실험으로 확인한다.

## 앱 통합

현재 `src/audio.ts`의 `record()`는 마이크를 열고 `finish()`는 `release()`를 통해 닫는다. `public/recorder-worklet.js`도 stop 메시지에서 PCM 수집을 종료한다. 따라서 마이크 세션의 시작·종료와 테이크 수집의 시작·종료를 분리해야 한다. `src/main.tsx`의 현재 수동 녹음·자동 재생 흐름은 감지 이벤트에서도 공유하되, 처리 중 중복 이벤트를 차단한다.

| 상태 | 트리거 처리 |
| --- | --- |
| 활성화 + 연습 화면 대기 | 감지 시 현재 선택 슬롯 녹음 시작 |
| 녹음 중 | 감지 시 한 번만 정지·저장·자동 재생 |
| 시작/종료/필터 준비 중 | 이벤트 무시, 이전 감지 결과 폐기 |
| 앱 재생 및 재생 직후 잔향 | 감지 결과로 제어하지 않음; 초기 버전은 재생 중 호출 미지원 |
| 설정에서 등록/미리 듣기 | 연습 녹음 전환 금지 |
| 체크 해제 | 대기 감지 종료, 다른 녹음 용도가 없으면 마이크 해제 |
| 권한 거부, 트랙 종료, 컨텍스트 중단 | 감지 중 표시 해제, 재개 필요 상태 안내 |

감지 지연 때문에 정지 신호가 원본 끝에 포함될 수 있다. 감지 구간을 PCM 샘플 위치로 추적하고 재생 종료점을 호출 소리 앞에 두는 방식을 우선 검토한다. 원본은 보존하고 사용자가 범위를 수정할 수 있어야 한다. 시작도 짧은 순환 버퍼와 감지 끝 위치를 이용해 첫 연주 어택이 잘리지 않는지 확인한다.

## 설정 UI 제안

**Trigger sound — 소리로 녹음 제어**

- `[트리거 소리 녹음하기]` (등록 후 다시 녹음/들어보기/삭제)
- `[ ] Trigger sound 활성화` (유효한 등록 샘플이 있어야 활성화)
- 상태: 미등록 / 등록됨 / 감지 중 / 재생 중 일시 정지 / 마이크 재개 필요
- 안내: “활성화하면 앱을 사용하는 동안 마이크로 소리를 감지합니다.”
- 선택적 감지 시험과 샘플 추가. 임계값은 우선 시험으로 보정하고 필요할 때 민감도 조정을 노출한다.

등록 PCM·특징·설정은 로컬에 저장하고 기존 로컬 데이터 전체 삭제에 포함한다. 활성화 선호를 저장하더라도 새 페이지에서 마이크가 실제로 열린 것처럼 표시하지 않는다. 권한과 AudioContext 재개가 성공한 뒤 실제 감지 상태를 표시한다.

## 항상 듣기의 범위

첫 버전 목표는 전면에서 열려 있는 웹 앱이다. 브라우저/OS가 입력과 AudioContext를 중단할 수 있으므로 화면 잠금·백그라운드 상시 감지를 보장하지 않는다. iOS Safari는 페이지 이탈이나 화면 꺼짐 시 AudioContext가 interrupted 상태가 될 수 있다. 화면 복귀·기기 변경 시 상태를 다시 검증한다.

화면 잠금 이후에도 감지가 필요하면 별도 네이티브 작업으로 분리한다. Android에는 microphone foreground service와 while-in-use 권한/시작 제한이 있으며 현재 Capacitor 스캐폴드만으로 해결되지 않는다. 지속 입력과 특징 추출의 배터리 비용도 실기기에서 측정한다.

## 구현 전 실험과 통과 판단

등록에 사용하지 않은 반복 소리, 거리·음량·속도 변화, 조용한 방과 생활 소음, 실제 연주 중 유사한 화음/어택으로 평가한다. 같은 샘플 파일을 다시 넣어 일치하는지만 확인해서는 정확도를 판단할 수 없다.

검출률, 장시간 연주당 오탐 횟수, 신호 종료부터 동작까지 지연, Worker 처리 시간·메모리·배터리, 정지 경계 오차를 기록한다. 무음·일반 연주에서의 오탐과 재생 자기 트리거를 특히 확인한다. 실제 데이터 없이 정확도 수치나 최적 임계값을 확정하지 않는다.

상태 전환 검증은 중복 검출, 수동 버튼과 감지의 동시 입력, 기능 해제, 등록 취소, 권한 실패, 트랙 중단, 페이지 복귀, 데이터 삭제를 포함한다. 이후 Chrome 및 iPhone Safari 실기기로 입력·재생·감지의 동시 동작을 검증한다.
